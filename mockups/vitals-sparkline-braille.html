vitals · sparkline + bar (braille)

same three variants as the block-character version, but the sparklines use braille. braille is denser, not wider — each character carries 2 samples (one per dot column) so the same horizontal slot holds 2× the history. trade-off: 4 height levels per sample instead of 8. for trend reading that's still plenty; for absolute value you have the bar.

empty cells of the bar are filled with braille sparkline of recent samples — each empty cell holds 2 samples. mv at 25%: 15 empty cells × 2 = 30 samples of history visible. as a vital recovers, the sparkline shrinks; at 100% the bar is all filled and no history is shown (because you don't need it).

density per character: block (▁▂▃▄▅▆▇█) → 1 sample, 8 height levels. braille → 2 samples, 4 height levels per sample. for a sparkline you read shape not absolute values, so the level reduction barely matters and the sample density doubles. the dots read more like btop / plotext than the smooth area-chart feel of block characters.
font note: braille requires JetBrains Mono Bundled first in the sparkline stack because Berkeley Mono Nerd Font's bundled TTF registers braille codepoints but stores empty glyphs for them — using berkeley would render nothing.
